# Deviations from SRS / SAD / Test Plan

| Item | Documented | What we did | Why |
|---|---|---|---|
| Profile and applications storage | PostgreSQL | In-memory stores (data resets on restart) | Faster for Sprint 1, same approach as drives |
| Mock-interview booking (F-015) | Booking stored in PostgreSQL; peer or senior reviewers | Slots and bookings kept in memory (backend/data/mockInterviewsStore.js) with 3 seeded slots; any student account can offer a slot and act as reviewer (no separate senior role); booking only, no video call | Same Sprint in-memory approach; the SRS allows the interview itself to happen outside the portal |
| Eligible drives route | GET /api/drives?studentId | GET /api/drives/eligible | GET /api/drives is the TPO list; student id comes from the token |
| Dev token script | Login issues JWT | backend/make-token.js creates test tokens | Used to test before login (F-002) was merged |
| Resume storage | Cloud object storage | Resumes kept in server memory (lost on restart) | Faster for Sprint 2, same approach as other stores |
| Users storage | PostgreSQL | In-memory store (backend/data/usersStore.js) | Same Sprint 1 in-memory approach as drives, profiles, and applications |
| Email / OTP delivery | Transactional email service / SMTP | In-memory OTP + console.log output (5 min expiry) | No live email service configured for Sprint 1; OTP logged to server console for testing |
| Resume template | Template saved with the profile | JSON template built from the profile; adjusted version kept in memory | Faster for Sprint 2; PDF export not built |
| Sensitive values in logs (NF-003) | Passwords, tokens and OTPs never logged | Dev-only OTP printed to the server console | No email service yet; everything else checked by backend/test-no-plaintext.js |
| Front end | React single-page app | Plain accessible HTML/JS page served by Express (backend/public/index.html) | Faster for Sprint 2; same REST API |
| Password reset email (F-003) | Reset link sent to institutional email via transactional SMTP | In dev mode the reset link is printed to the server console prefixed `[EMAIL DEV]`; the raw token is NOT stored in plaintext and is NOT returned in API responses. Production SMTP requires `EMAIL_PROVIDER` + `SMTP_*` env vars — see `backend/utils/emailService.js`. | No live SMTP service available in Sprint 2 development environment |
| Password reset token storage (F-003) | Tokens stored securely | Only the SHA-256 digest of each reset token is stored in the in-memory map; the raw token travels exclusively inside the HTTPS reset URL | Follows same in-memory approach as OTP; satisfies AC-003 "store only a cryptographic hash" |
| Account lockout HTTP status (SR-004) | SRS specifies account locking; no HTTP code mandated | HTTP 423 Locked returned for an active lockout; error_code `ACCOUNT_LOCKED` | RFC 9110 §15.5.24 — 423 is the semantically correct code for a temporarily locked resource; consistent with existing error_code convention |
| Account lockout storage (SR-004) | Persistent lock state | `failedLoginAttempts` and `lockedUntil` stored in the same in-memory user record | Consistent with Sprint 2 in-memory approach; state resets on server restart |
| HTTPS / TLS termination (SR-001) | TLS terminated at application or reverse proxy | TLS terminated directly in the Node.js process using the built-in `https` module; `minVersion: 'TLSv1.2'` set explicitly; TLS 1.3 supported (Node default max) | Satisfies SR-001 without requiring an external reverse proxy in this deployment |
| TLS certificate (SR-001) | Trusted CA certificate in production | Development/test uses a self-signed certificate generated by `backend/scripts/gen-dev-cert.js`; cert and key are gitignored. Production requires `TLS_CERT_PATH` + `TLS_KEY_PATH` env vars pointing to a CA-issued certificate | No CA-issued certificate available in the Sprint 2 development environment |
| TLS 1.0 / 1.1 rejection mechanism (SR-001) | Server must reject TLS < 1.2 | Node.js 22 with OpenSSL 3 disables TLS 1.0 and 1.1 at the OpenSSL library level; additionally `minVersion: 'TLSv1.2'` is set on every `https.createServer()` call to enforce this independently of the OpenSSL build configuration | Defence-in-depth: library default plus explicit server configuration |
| Availability monitoring storage (NF-002) | 30-day persistent monitoring records | Check logs and incident history are held in memory (last 1000 entries) in `AvailabilityMonitor` | Consistent with Sprint 2 in-memory architecture for drives, users, profiles, and applications; production deployments should pipe check logs to persistent storage or external uptime services |
| Concurrent users (NF-005) | 2,000 students, p90 within 3 s | Tested up to 2,000; passes at 500 (p90 948 ms), fails at 1,000+ (about 16% refused connections at 2,000) | Single laptop, in-memory storage; see PR #48 and backend/test-load.js. Not met on this setup |
| Mock tests and attempts (F-011) | Tests and attempts stored in PostgreSQL | 4 seeded tests and all attempts kept in memory (backend/data/mockTestsStore.js); timer enforced on the server, expired attempts auto-submitted by a 1-second sweep | Same Sprint in-memory approach as the other stores; MOCK_TEST_SECONDS env var shortens the timer for testing only |
